## Architecture Overview

The retained application is a Rust service/library with a framework-free TypeScript browser and checked-in generated assets. Node is development tooling, not a backend.

Canonical write -> existing SQLite transaction -> typed shared interpretation -> saved display blocks/entries/field descriptors/chunks -> committed canonical/projection head.

Display read -> existing owned storage operation -> session lock and connection -> short consistent read transaction -> indexed projection lookups -> compact shared byte-accounted values -> release transaction/connection ownership before return.

Future HTTP adapters and the browser consume the same closed representation. They must not replay raw events to rebuild it. B2 continues to read its established canonical provider context independently.

Shared conversation values have private fields and public getters. Crate-private validated constructors allow sibling storage construction. Native numeric values become canonical decimal strings through the closed shared encoder. Arbitrary provider/native JSON is never generically converted into display JSON.

## Key Patterns Discovered

- Storage reads use StoreInner::operation(false, ...), existing session ownership and database retirement paths. A dropped waiter does not cancel admitted owned SQL.
- Explicit session open performs migration. Ready-schema reads do not repair or backfill corrupted projections.
- Do not call full run_record or scan canonical payloads to construct a compact block header. The saved header is the read source.
- Entry positions remain chronological. Reverse SQL selection produces bounded suffixes; returned fragments/entries are forward chronological.
- Field IDs are literal text for the human sentinel or derived lowercase 64-hex identities. Syntax acceptance alone does not establish entry membership.
- OrderKey carries authoritative fallback placement at the first answer's original content index. SourceKey identity is independent of that placement.
- An incompatible lower-order field insertion advances content_epoch. Higher-order insertion and compatible existing-field growth retain appropriate old traversal membership.
- Shared DisplayJson counting and serialization use the same adapters. Include escaping, cursor and envelope overhead, not just stored text lengths.
- Transfer limits are not stored-content lifetime limits. Large human/tool/assistant fields remain fully stored and traversable.
- Tool result_recorded, finish_recorded and is_error are separate facts. A result body that looks like an error is not enough to invent is_error.
- Keep static diagnostics and privacy boundaries. Do not save raw headers, credentials, private provider payloads or large assertion bodies.
- SQLx fixture helpers have exposed dynamic-SQL and lifetime problems before. Preserve genuine independent old-schema fixture bytes; adapt only current prospective-admission fixtures where required.

### A5b2: implement SessionHandle::conversation_page

Required public shape: conversation_page(&self, query: ConversationQuery) -> Result<ConversationPage, ConversationError>. Query variants are Latest, Before(BlockCursor), Within(ActivityCursor). ActivityCursor is the current Rust name; do not invent or rename it to SliceCursor.

Scope:

- Latest selects the newest human block by the indexed accepted position, not the most recently renamed session or last raw event. It returns that block and its bounded latest activity segment without fetching/decode of older block content.
