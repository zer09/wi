# G1.1 identifier amendment and boundary audit

Owner amendment: October 1, 2026. This changes new-input admission, not pagination, stored history, or authentication. This document is a contract and source audit. Execution evidence belongs in VERIFICATION_G1_1.md and verification-g1.1.json.

## Required correction

Wi request IDs must be canonical, non-nil UUIDs: exactly 36 ASCII characters in lowercase hyphenated spelling. Parsing must equal that spelling without normalization. UUID generation uses v4; validation does not require v4. This matches src/storage/ids.rs:31-37.

Reject malformed and oversized new identifiers. Do not truncate, hash, paginate, silently rewrite them, or add a partial-summary marker. Identifier validity is not a task quota or a history cap. Public String fields do not remove this validation requirement.

Validate request receipts before the controller increments the admitted counter or assigns request state and summary.last_request_id. Generation has already been polled; retain Unknown upstream outcome on malformed receipt. Preserve a previous valid last_request_id if a later receipt is invalid. Close through existing cleanup. Do not observe the rejected request's event stream or dispatch its tools. Test that the resulting failure can be persisted through the real controller and SQLite.

Strict novel storage admission covers runtime run/event/turn/request IDs, nested request IDs, RunFinished.summary.last_request_id, ToolResult.request_id, and direct RunResult.run_id/summary.last_request_id. Preserve optional absence where the existing lifecycle permits it. Validate supported OpenAI local provider-session UUIDs and provider-envelope composites at producer and storage boundaries using the actual accepted provider context. Binding and direct Result paths must not bypass the checks. A false nested provider label must not bypass the supported-provider rule.

The OpenAI envelope event ID is not a UUID. Its defined spelling is `<provider-session UUID>:<positive canonical decimal sequence>`, with the sequence equal to envelope.sequence. Its maximum spelling is 57 ASCII bytes. Do not replace it with a UUID. Generic provider identifiers need a separate format decision, not coercion to the OpenAI spelling.

Resolve an existing operation receipt before validating a novel append. An exact historical retry returns its original receipt; changed payload retains storage.command_conflict. Preflight the complete new batch before canonical inserts. Reject invalid identifiers with static storage.invalid_input and existing commit-certainty semantics. Preserve canonical events, commands, projections, manifest head, and receipts on rejection.

Keep historical structural decoding separate from strict new admission. In particular, do not tighten records::validate_runtime, RecordedProviderBinding construction, or shared binding-read validation so that formerly accepted canonical bytes become unreadable. Preserve raw API1, migration, repair, and B2 reads. Preserve independently populated schema1/2 fixtures and their byte/digest expectations. Change only current producer/append fixtures that now submit invalid Wi-owned identifiers.

## Existing-data conflict and original evidence

The pre-amendment storage boundary could accept non-UUID or oversized request IDs through custom producers or direct appends. Normal generation does not prove that every stored record uses normal generation. Existing raw-SQL schema fixtures deliberately exercise old opaque IDs and remain compatibility evidence.

The original reproducer is src/storage/conversation/bounded_header_tests.rs, SHA256 `54e73efe544d343db05e1beee025f69d95816dd4e20144875886484c2be467f8`. Its passing observation committed 524,289 bytes in summary.last_request_id; the human anchor encoded to 506 bytes, but the block could not fit 524,288 bytes. The parent archived the exact source at evidence/bounded_header_tests.pre_identifier_amendment.rs.txt and verified byte equality and the same SHA256 before replacement. Preserve this artifact and the passing observation when replacing the active reproducer with rejection regressions.

Prospective rejection resolves this input defect for new writes. It cannot make a genuinely pre-existing oversized summary displayable under the unchanged mandatory summary and page budget. The owner subsequently approved an explicit display-read error for this legacy case. Do not classify formerly accepted bytes as corruption, alter raw history or omit mandatory data. See the approved disposition below.

## Approved legacy display-read disposition

The owner answered Yes to the explicit display-read error proposal. An otherwise readable legacy block whose mandatory header cannot fit the fixed response budget returns ConversationError::DisplayUnavailable. The HTTP adapter maps it to the existing flat ErrorView with api.conversation_display_unavailable/422 and a static diagnostic. This is a read-only representation failure, not invalid new input, corruption, task failure or evidence of rollback. Do not include identifiers, content, paths or cursor diagnostics in the error.

Apply exact shared encoded-size accounting after allowing compact human/entry fragments to shrink while retaining required progress. Do not reject a legacy header merely because a full-sized preview leaves insufficient space. Fail the addressed response without partial success, omission, a partial-summary marker, paged ID, truncation, rewrite or silent block skipping. Canonical bytes, raw history, migration and execution state remain unchanged. Other representable blocks remain readable. No real user data was inspected.

The Rust disposition and entry/content regressions are implemented and passed all three scoped A5b1 reviews; see A5B1_READS.md. HTTP/SSE and the specified 422 mapping are not implemented. General native/generic ID formats and managed/account compatibility remain open; the owner invited focused questions.
